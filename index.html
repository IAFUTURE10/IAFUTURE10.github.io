Antes de reparar un error, averigua qué está fallando

Un mismo mensaje puede tener varias causas. Este punto de partida te ayuda a describir el problema, separar una avería de equipo de una de conexión y elegir una comprobación que puedas deshacer. Las guías de Código Error explican qué observar y cuándo detenerse; no prometen arreglar cualquier dispositivo.

Si hay riesgo de perder información, detente. Un disco que hace ruidos nuevos, un equipo con olor a quemado, una batería hinchada o archivos que dejan de abrirse no son casos para seguir probando reinicios, formateos o limpiadores. Apaga y desconecta el equipo cuando sea seguro y solicita asistencia técnica. Una copia de seguridad y un punto de restauración cumplen funciones distintas: el segundo no sustituye tus archivos.

Elige por el síntoma, no por la primera solución que encuentres

El equipo inicia, pero falla una aplicación

Anota el nombre y versión de la aplicación, el mensaje completo y la acción que lo provoca. Prueba un archivo de ejemplo sin datos personales: si funciona, el problema puede estar en el archivo o en una extensión.

Comprobar aplicaciones

Hay Wi-Fi, pero una página no abre

Comprueba una segunda web y otro dispositivo en la misma red. Si solo falla una página, reiniciar todo el equipo no ayuda a distinguir una caída del servicio de un bloqueo local.

Delimitar un fallo de conexión

Windows muestra un código

Copia exactamente el código y dónde apareció: al actualizar, instalar o arrancar. Un código sin su contexto no basta para elegir un procedimiento.

Diagnóstico de Windows

El navegador se queda en blanco o da error

Compara la misma dirección en una ventana privada y otro navegador. Una prueba privada ayuda a aislar datos de sesión o extensiones, pero no demuestra por sí sola cuál es la causa.

Cambia una sola cosa cada vez. Anota el estado anterior, la prueba y el resultado. Si modificas DNS, controladores, permisos y aplicaciones a la vez, no podrás saber qué funcionó ni volver al estado inicial con confianza.

Registro que puedes copiar para pedir ayuda

Este ejemplo muestra el nivel de detalle útil. Sustituye cada línea por lo que observaste; deja «no comprobado» donde falte una prueba. Oculta correos, claves, direcciones IP públicas, identificadores personales y nombres de archivos privados antes de compartir capturas.

Equipo y sistema: portátil; versión de Windows anotada desde Configuración.
Acción: abrir la página de acceso de una aplicación.
Mensaje exacto: copiado del navegador, sin resumirlo como «no funciona».
Alcance: otras dos páginas abren; esa misma dirección abre en otro dispositivo de la misma red.
Inicio del fallo: primera observación y últimos cambios conocidos, sin dar por probada una causa.
Pruebas: ventana privada: mismo error; otro navegador: no comprobado.
Datos protegidos: no se han borrado archivos ni restablecido el sistema.

Con este registro, la siguiente prueba razonable sería comparar otro navegador en el dispositivo afectado. Borrar todos los datos del equipo todavía no está justificado: la evidencia apunta a un problema más limitado.

Qué no conviene hacer durante una primera comprobación

  • No descargues «reparadores» que prometen resolver cualquier código ni instales controladores de una fuente que no puedas identificar.
  • No desactives permanentemente las protecciones del sistema para que desaparezca un mensaje.
  • No ejecutes comandos que borren, formateen o cambien permisos recursivamente si no entiendes su alcance.
  • No restablezcas un equipo que depende de una cuenta de trabajo sin consultar a su administrador.
  • No compartas contraseñas o códigos de recuperación con quien te ofrezca ayuda.
